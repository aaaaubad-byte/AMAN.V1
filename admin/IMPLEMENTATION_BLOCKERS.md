# عوائق تطبيق Admin — حالة AMAN-2

**الحالة:** عولجت فجوات المصدر والعقود المذكورة أدناه على مستوى المستودع، لكن القبول الحي/الإنتاجي غير مكتمل. لا تستخدم هذه القائمة لتجاوز صلاحيات Backend أو لتوليد بيانات تجريبية.

## بوابات مفتوحة

### B-DB-001 — قاعدة Supabase المقصودة غير متاحة للتحقق
- لم تُجرَ مصادقة أو قراءات/RPC حية، ولم يُنفذ SQL.
- migrations 001–004 مصدرية فقط؛ خصوصًا 004 لم تُطبق.
- المطلوب لاحقًا: تهيئة المشروع المقصود وتفويض منفصل لأي تطبيق SQL؛ تحقق schema وRLS وpermissions وatomicity/audit/idempotency في البيئة المصرح بها.

### B-ENV-001 — إعدادات التشغيل غائبة
- لا قيم `SUPABASE_URL` و`SUPABASE_ANON_KEY` للمشروع المقصود.
- التطبيق يعرض عدم التهيئة ولا يحاكي تسجيل الدخول. لا تُضمّن `service_role`.

### B-TEST-001 — لا جهاز/محاكي في التحقق الحالي
- اجتاز المصدر واختبارات الوحدة، لكن لم تُختبر الواجهة وتدفقات Auth/Offline على جهاز أو محاكي.
- لا توجد لقطات مرجعية كافية لمقارنة بصرية بكسلية.

### B-API-001 — تنفيذ الدفع الخارجي ليس جزءًا من التطبيق
- A07 يسجل الإكمال والمرجع بعد أن ينفذ مشغل مخول الدفع عبر القناة الخارجية؛ لا يدعي التطبيق إرسال الأموال أو استخدام مزود دفع غير موثق.
- قبل الإنتاج: تحقق الإجراء اليدوي وسجل التدقيق/المحاسبة مع صاحب النظام، أو اعتمد تكاملًا منفصلًا مخولًا.

## عوائق مصدرية أُغلقت، وتحتاج تحققًا حيًا فقط

| النطاق | المعالجة في المصدر |
|---|---|
| صلاحيات Admin دقيقة | role/permission checks وRLS/RPC من migrations السابقة، والتحقق في الواجهة مع إعادة التحقق بالخادم |
| A06 | اعتماد/رفض طلب الشراء بعقود RPC وسبب الرفض ومفتاح idempotency وفق المصدر |
| A07 | قراءة المهام، التنفيذ بعد مرجع الدفع الخارجي، إعادة الجدولة والإلغاء والتخطيط عبر RPC الحالي |
| A08 | Provider وPrefix وTariff CRUD/تفعيل/تعطيل؛ migration 004 تضيف RPCs إدارية مدققة للبادئات والتعرفات |
| A09/A10/A11 | نماذج الباقات ووسائل الدفع وإعدادات المهام، مع تحقق حقول محلي وBackend RPC |
| A13 | بحث مستلم، تأكيد الإرسال، `send_admin_notification`؛ التسليم في `notifications` وسجل الحملات في `admin_notifications` الموجود مسبقًا |
| A14 | أنواع تقارير وفترات/شركة حيث تنطبق، وCSV بعد فحص صلاحية التصدير |
| A04 | لا تحرير لرقم الهاتف ولا Edit RPC؛ تغيير حالة علاقة الرقم فقط بما يسمح به العقد |
| الجلسة والOffline | تجديد جلسة Auth، إعادة التحقق من الدور، cache مشفر للقراءة فقط، إيقاف mutations عند Offline |

## سجل تحقق AMAN-2

- `./gradlew testDebugUnitTest --no-daemon --console=plain`: ناجح، 7 اختبارات، ترجمة Kotlin ناجحة.
- `database/AMAN_DATABASE_FINAL.sql` يطابق migrations 001–004 بالتركيب الحرفي.
- لم يُنفذ SQL ولم يتم اتصال حي. فحص `pglast` لم يجرِ في checkpoint الأخير لأن الحزمة غير مثبته (`ModuleNotFoundError`).
- لا APK مطلوب أو مسلم. لا تغييرات على `customer/`.

لخطوات الاستئناف والحدود التفصيلية ارجع إلى `../MANUS/HANDOFF.md` و`../MANUS/PHASE_2_STATE.md`.
